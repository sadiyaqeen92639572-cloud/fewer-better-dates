# Fewer Better Dates

Live: [fewerbetterdates.com](https://fewerbetterdates.com)

A fake-door waitlist testing demand for a different kind of dating product:
8 weeks, 6 curated introductions, no swiping. The site collects qualified
signups across six cities to see where the concept actually resonates before
any matchmaking product gets built.

## What's in this repo

- `index.html` — homepage: pitch, process, waitlist form (city selector: London,
  Manchester, Norwich, New York, Atlanta, Austin).
- `journal/` — three editorial articles (why dating is hard, why am I still
  single, how to find love), each cross-linked to the city guides.
- `dating/` — programmatic city dating guides (`dating/<city>/`), generated by
  `generate-city-pages.js` from sourced, dated stats in `city-data.js`. Each
  page is a real local dossier (population, single share, median age, local
  meet-people ideas), not a template swap — a city only publishes once it has
  real sourced material for the required stats.
- `about/`, `privacy/` — publisher identity (Gesmine-Invest Limited) and data
  policy for the waitlist.
- `functions/api/waitlist.js` — Cloudflare Pages Function handling waitlist
  submissions: validates email, honeypot spam field, hashes IP, writes to D1.
- `assets/js/waitlist.js` — shared client script wiring every
  `form[data-waitlist-form]` to the API, reading UTM params into hidden fields.
- `schema.sql` — D1 `signups` table (city, qualification answers, UTM,
  hashed IP; unique per email+city).
- `sitemap.xml`, `robots.txt`, `llms.txt` — SEO/crawler surface, kept in sync
  by the generator.

## Stack

Static HTML + Cloudflare Pages Functions + Cloudflare D1. No build step for
the hand-written pages; city pages regenerate via:

```bash
node generate-city-pages.js
```

This rewrites `dating/**`, `dating/index.html`, and `sitemap.xml` from
`city-data.js` — never hand-edit generated city pages directly.

## Deploy

Connected to Cloudflare Pages with GitHub auto-deploy: pushing to `main`
builds and deploys automatically. D1 binding (`DB`) and the custom domain are
configured on the Pages project.
